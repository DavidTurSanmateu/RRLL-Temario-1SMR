    Anexo 1. Direccionamiento IPv4

    El protocolo IPv4 permite identificar los dispositivos de una red mediante direcciones IP. Estas direcciones se utilizan para que los datos puedan llegar desde un dispositivo de origen hasta su destino, incluso cuando ambos se encuentran en redes diferentes. Para comprender cómo se asignan las direcciones y cómo se determina si dos dispositivos pertenecen a la misma red, es necesario conocer su estructura, su representación binaria y el funcionamiento de las máscaras de red.

    Una dirección IPv4 tiene una longitud de 32 bits, divididos en cuatro grupos de 8 bits llamados octetos. Cada octeto puede representar un valor comprendido entre 0 y 255, por lo que las direcciones se escriben habitualmente en notación decimal separada por puntos. Por ejemplo, la dirección 138.2.214.254 está formada por los octetos 138, 2, 214 y 254.

    Aunque normalmente trabajamos con direcciones decimales, los equipos procesan las direcciones IP en binario. Cada octeto se convierte por separado utilizando las potencias de dos, desde 20 hasta 27. Por ejemplo, el octeto 138 se representa como 10001010, porque 128 + 8 + 2 = 138. Aplicando el mismo procedimiento a los cuatro octetos, la dirección 138.2.214.254 se representa en binario como 10001010.00000010.11010110.11111110.

    Al disponer de 32 bits, IPv4 permite representar 232, es decir, 4.294.967.296 direcciones diferentes. Sin embargo, no todas pueden asignarse a dispositivos de forma ordinaria, ya que algunas están reservadas para funciones específicas. Además, el crecimiento de Internet hizo que el espacio de direcciones IPv4 resultara insuficiente para atender la demanda, motivo por el que se desarrollaron mecanismos como la traducción de direcciones de red (NAT) y el protocolo IPv6, que dispone de un espacio de direcciones mucho mayor.

    Una dirección IPv4 contiene dos partes lógicas: la parte de red, que identifica la red a la que pertenece la dirección, y la parte de host, que identifica un dispositivo dentro de esa red. La separación entre ambas partes no viene determinada actualmente por la propia dirección, sino por el prefijo de red, que indica cuántos bits se utilizan para identificar la red.

    Históricamente, IPv4 se organizaba mediante un sistema de clases. Las direcciones de clase A comprendían, en términos generales, el primer octeto entre 1 y 127; las de clase B, entre 128 y 191; y las de clase C, entre 192 y 223. La clase D, de 224 a 239, se destinó a la multidifusión (multicast), mientras que el rango de clase E, de 240 a 255, quedó reservado para usos especiales y experimentales. Este sistema asignaba máscaras predeterminadas según la clase: 255.0.0.0 para A, 255.255.0.0 para B y 255.255.255.0 para C.

    La clasificación por clases es un sistema histórico y no debe utilizarse para determinar cómo se diseñan las redes actuales. Hoy se emplea principalmente el direccionamiento CIDR, que indica el tamaño de la parte de red mediante un prefijo escrito después de una barra. Por ejemplo, 192.168.1.25/24 indica que los primeros 24 bits identifican la red y los 8 restantes corresponden a la parte de host. Esta notación permite definir redes de distintos tamaños sin depender de las antiguas clases.

    La máscara de red permite identificar qué bits de una dirección pertenecen a la red y cuáles al host. En su representación binaria, los bits correspondientes a la red tienen valor 1 y los correspondientes al host tienen valor 0. Por ejemplo, la máscara 255.255.255.0 equivale a 11111111.11111111.11111111.00000000 y se expresa como /24. En cambio, la máscara 255.255.255.192 equivale a /26: sus primeros 26 bits son 1 y los seis restantes son 0.

    Para obtener la dirección de red se realiza una operación lógica AND entre la dirección IP y su máscara. Esta operación devuelve 1 únicamente cuando los dos bits comparados son 1; en los demás casos devuelve 0. Como consecuencia, los bits correspondientes a la red se conservan y los bits correspondientes al host se convierten en cero.

    Ejemplos: cálculo de la dirección de red

    Consideremos la dirección IPv4 193.128.214.254/24. Su máscara de subred es 255.255.255.0.

    Para obtener la dirección de red, convertimos la dirección IP y la máscara a binario y aplicamos la operación lógica AND bit a bit. Esta operación devuelve 1 únicamente cuando ambos bits tienen valor 1; en cualquier otro caso, devuelve 0.

    Dirección IP:  11000001.10000000.11010110.11111110
Máscara:       11111111.11111111.11111111.00000000
               -----------------------------------
Dirección red: 11000001.10000000.11010110.00000000

    En los tres primeros octetos, todos los bits de la máscara son 1, por lo que los bits correspondientes de la dirección IP se conservan. En el último octeto, todos los bits de la máscara son 0, por lo que el resultado es 0 en todas las posiciones.

    Para obtener la dirección de red en decimal, convertimos el resultado binario:

    • 11000001 = 193
    • 10000000 = 128
    • 11010110 = 214
    • 00000000 = 0

    Por tanto, la dirección de red es 193.128.214.0. Todas las direcciones de esta subred comparten los primeros 24 bits, mientras que los 8 restantes se utilizan para identificar los hosts.

    Consideremos la dirección IPv4 193.128.214.130/26. Su máscara de subred es 255.255.255.192.

    Para obtener la dirección de red, convertimos la dirección IP y la máscara a binario y aplicamos la operación lógica AND bit a bit. Esta operación devuelve 1 únicamente cuando ambos bits tienen valor 1; en cualquier otro caso, devuelve 0.

    Dirección IP:  11000001.10000000.11010110.10000010
Máscara:       11111111.11111111.11111111.11000000
               -----------------------------------
Dirección red: 11000001.10000000.11010110.10000000

    En los tres primeros octetos, todos los bits de la máscara son 1, por lo que los bits correspondientes de la dirección IP se conservan. En el último octeto, los dos primeros bits de la máscara también son 1, por lo que se conservan los dos primeros bits de la dirección IP. Los seis bits restantes de la máscara son 0, por lo que los seis bits correspondientes del resultado también son 0.

    Para obtener la dirección de red en decimal, convertimos el resultado binario:

    • 11000001 = 193
    • 10000000 = 128
    • 11010110 = 214
    • 10000000 = 128

    Por tanto, la dirección de red es 193.128.214.128. Los primeros 26 bits identifican la red y los 6 restantes corresponden a los hosts. Este ejemplo muestra que la parte de red puede terminar en mitad de un octeto; por eso no siempre basta con fijarse en los tres primeros números de una dirección.

    Además de la dirección de red, cada subred IPv4 tiene una dirección de difusión (broadcast), utilizada para enviar paquetes a todos los dispositivos de esa subred. Para calcularla, se conservan los bits de red y se ponen a 1 todos los bits de host. Esta dirección no se asigna normalmente a ningún dispositivo.

    Ejemplos: cálculo de la dirección de difusión

    Consideremos la subred 193.128.214.0/24. Su máscara es 255.255.255.0, por lo que los primeros 24 bits corresponden a la red y los 8 restantes a los hosts.

    Para calcular la dirección de difusión, conservamos los bits de red y ponemos a 1 los ocho bits de host:

    Dirección de red:    11000001.10000000.11010110.00000000
Dirección difusión:  11000001.10000000.11010110.11111111

    El último octeto, 11111111, equivale a 255 en decimal. Por tanto, la dirección de difusión es 193.128.214.255.

    Consideremos ahora la subred 193.128.214.128/26. Su máscara es 255.255.255.192, por lo que los primeros 26 bits corresponden a la red y quedan 6 bits para los hosts.

    En este caso, conservamos los 26 bits de red y ponemos a 1 los seis bits restantes:

    Dirección de red:    11000001.10000000.11010110.10000000
Dirección difusión:  11000001.10000000.11010110.10111111

    El último octeto, 10111111, equivale a 191 en decimal. Por tanto, la dirección de difusión es 193.128.214.191.

    En las subredes IPv4 convencionales, la dirección de red y la dirección de difusión no se asignan a dispositivos como direcciones de host ordinarias. Así, en la subred 193.128.214.128/26, el rango habitual de direcciones asignables es de 193.128.214.129 a 193.128.214.190. Esta subred dispone de 64 direcciones en total, de las cuales 62 son utilizables habitualmente por hosts. En general, si una subred tiene h bits para hosts, dispone de 2h direcciones; en las subredes convencionales se restan dos para obtener el número habitual de direcciones asignables, una para la red y otra para la difusión. Existen excepciones, como los prefijos /31 empleados en determinados enlaces punto a punto.

    También hay direcciones IPv4 con funciones especiales. La dirección 127.0.0.1, por ejemplo, es la dirección de loopback o bucle local, que permite a un equipo comunicarse consigo mismo sin enviar los paquetes a otro dispositivo de la red. El bloque 127.0.0.0/8 está reservado para esta función. Por su parte, 0.0.0.0 tiene un significado que depende del contexto: puede representar una dirección de origen aún no configurada y, en una tabla de rutas, 0.0.0.0/0 identifica la ruta predeterminada, que se utiliza cuando no existe una ruta más específica para el destino.

    Otra dirección especial es 255.255.255.255, conocida como dirección de difusión limitada. Permite enviar un paquete de difusión a los dispositivos de la red local, pero los routers no deben reenviarlo a otras redes. No debe confundirse con la dirección de difusión de una subred concreta, que depende de su prefijo y puede tener un valor diferente.

    En definitiva, para trabajar con IPv4 es fundamental distinguir entre la dirección IP de un dispositivo, la máscara o prefijo que define su subred, la dirección de red que identifica esa subred y la dirección de difusión que permite enviar paquetes a todos sus hosts. La operación AND entre la IP y la máscara permite calcular la dirección de red; para calcular la difusión, se mantienen los bits de red y se establecen a 1 todos los bits de host. Comprender esta diferencia permite interpretar direcciones, determinar qué dispositivos pertenecen a una misma subred y calcular el rango de direcciones disponibles.
