    3. La familia de protocolos TCP/IP

    La familia de protocolos TCP/IP es el conjunto de protocolos que permite la comunicación entre dispositivos conectados a una red. Es la arquitectura de protocolos utilizada en Internet y también constituye la base de las comunicaciones en la mayoría de las redes locales actuales.

    TCP/IP no es un único protocolo, sino una familia formada por diferentes protocolos que realizan funciones complementarias. Algunos se encargan del direccionamiento y del envío de paquetes, otros proporcionan mecanismos de transporte y otros permiten ofrecer servicios de red concretos.

    En este apartado se estudian algunos de los protocolos y herramientas fundamentales de TCP/IP, así como el direccionamiento IP y las principales utilidades empleadas para configurar y diagnosticar una red.

    3.1. Los protocolos básicos en TCP/IP

    La arquitectura TCP/IP organiza las funciones de comunicación en diferentes niveles. Aunque su correspondencia con el modelo OSI no es exactamente la misma, permite distinguir las funciones relacionadas con el acceso a la red, el direccionamiento, el transporte y los servicios de aplicación.

    En una red TCP/IP intervienen numerosos protocolos. Entre los más importantes para comprender el funcionamiento básico de una red se encuentran IP, ICMP, TCP, UDP y ARP.

    A. Protocolo IP

    IP (Internet Protocol) es el protocolo encargado del direccionamiento y del encaminamiento de los paquetes entre dispositivos. Cada interfaz de red utiliza una dirección IP que permite identificarla dentro de una red.

    IP proporciona un servicio de comunicación no orientado a conexión y sin garantía de entrega. Esto significa que el protocolo IP se encarga de intentar llevar los paquetes hasta su destino, pero no garantiza por sí mismo que lleguen, que lleguen en el orden correcto o que no se produzcan pérdidas.

    Cuando los datos procedentes de niveles superiores deben atravesar una red, IP los transporta mediante paquetes o datagramas IP. Los routers utilizan las direcciones IP de destino para decidir por qué interfaz deben reenviar estos paquetes hasta aproximarlos a su destino.

    Actualmente existen principalmente dos versiones del protocolo:

    • IPv4, que utiliza direcciones de 32 bits, como 192.168.1.10.
    • IPv6, que utiliza direcciones de 128 bits y fue desarrollado para disponer de un espacio de direccionamiento mucho mayor que IPv4. Por ejemplo, 2001:0db8:85a3:0000:0000:8a2e:0370:7334.

    En las redes locales es habitual encontrar todavía IPv4, mientras que IPv6 se utiliza cada vez más y forma parte de las tecnologías actuales de redes.

    B. Protocolo ICMP

    ICMP (Internet Control Message Protocol) se utiliza para transmitir mensajes de control y de diagnóstico relacionados con IP. No está destinado a transportar directamente los datos de las aplicaciones, sino a informar sobre determinadas situaciones que se producen durante las comunicaciones.

    Por ejemplo, ICMP permite que un dispositivo pueda informar de determinados errores relacionados con la entrega de paquetes. También se utiliza en herramientas de diagnóstico como ping, que envía mensajes ICMP de solicitud de eco y comprueba si recibe una respuesta.

    C. Protocolo TCP

    TCP (Transmission Control Protocol) es un protocolo de la capa de transporte orientado a conexión. Su función es proporcionar una comunicación fiable entre dos aplicaciones que intercambian datos a través de una red IP.

    TCP establece una conexión entre los extremos de la comunicación y utiliza mecanismos como la numeración de segmentos, las confirmaciones y la retransmisión de datos para controlar la entrega. De esta forma, puede detectar pérdidas y solicitar nuevamente los datos que no hayan llegado correctamente.

    TCP resulta adecuado para aplicaciones en las que es importante que los datos lleguen de forma fiable y ordenada. Entre sus usos se encuentran numerosas comunicaciones web, el correo electrónico y otros servicios de red.

    Las aplicaciones utilizan puertos para identificar los servicios con los que desean comunicarse. Una combinación de dirección IP y puerto permite identificar un extremo concreto de una comunicación de red.

    D. Protocolo UDP

    UDP (User Datagram Protocol) es un protocolo de transporte no orientado a conexión. A diferencia de TCP, no establece una conexión previa ni proporciona mecanismos propios para garantizar que los datos lleguen a su destino, ni que lo hagan en el mismo orden en que fueron enviados.

    Esta simplicidad hace que UDP tenga una menor sobrecarga que TCP y pueda resultar apropiado cuando se necesita reducir la latencia o cuando la propia aplicación se encarga de controlar determinados aspectos de la comunicación.

    Por tanto, la diferencia fundamental puede resumirse de la siguiente manera:

    TCP UDP
    Orientado a conexión No orientado a conexión
    Proporciona entrega fiable No garantiza la entrega
    Mantiene el orden de los datos No garantiza el orden
    Tiene mayor sobrecarga Tiene menor sobrecarga
    Adecuado cuando la fiabilidad es prioritaria Adecuado cuando se busca rapidez o baja sobrecarga

    E. Protocolo ARP

    ARP (Address Resolution Protocol) permite relacionar una dirección IPv4 con la dirección MAC correspondiente dentro de una red local. Esta relación es necesaria porque un dispositivo puede conocer la dirección IP del destino, pero necesita conocer también su dirección MAC para poder entregar una trama Ethernet dentro de la red local.

    Cuando un equipo necesita conocer la dirección MAC asociada a una dirección IPv4 de su red local, puede realizar una solicitud ARP. El dispositivo que utiliza esa dirección IPv4 responde indicando su dirección MAC. La relación obtenida se almacena temporalmente en una caché ARP para evitar tener que realizar la consulta en cada comunicación.

    ARP está asociado a IPv4. IPv6 utiliza mecanismos diferentes, integrados en ICMPv6, para realizar la resolución de direcciones en la red local.

    3.2. El direccionamiento de red en TCP/IP

    Para que los dispositivos puedan comunicarse mediante IP es necesario disponer de un sistema de direccionamiento. En IPv4, cada interfaz de red utiliza una dirección de 32 bits, que normalmente se representa mediante cuatro números decimales separados por puntos. Cada uno de estos números puede tener un valor entre 0 y 255.

    Por ejemplo:

    192.168.1.25

    Una dirección IPv4 no debe interpretarse simplemente como un identificador de un equipo. Una parte de sus bits identifica la red o subred, mientras que otra parte identifica el host dentro de esa red. La máscara de subred permite determinar dónde termina la parte correspondiente a la red y dónde comienza la correspondiente al host.

    A. Direccionamiento basado en clases

    Históricamente, las direcciones IPv4 se dividían en diferentes clases de red: A, B, C, D y E. Las clases A, B y C se utilizaban para redes de diferentes tamaños, mientras que la clase D se destinaba a multidifusión y la clase E a usos experimentales o reservados.

    En el direccionamiento por clases, los primeros bits de una dirección IPv4 permitían determinar a qué clase pertenecía. En las clases A, B y C, esta clasificación establecía cuántos bits se destinaban a identificar la red y cuántos al dispositivo (host). De esta manera, se asignaban bloques de direcciones de distintos tamaños según las necesidades de cada organización.

    Las principales características de las clases eran las siguientes:

    • Clase A: se diseñó para redes muy grandes, con una gran cantidad de dispositivos. Utilizaba el primer octeto para identificar la red y los tres restantes para identificar los hosts. Comprende las direcciones desde 0.0.0.0 hasta 127.255.255.255. Su máscara tradicional era 255.0.0.0 (/8).
    • Clase B: se destinaba a redes de tamaño intermedio. Utilizaba los dos primeros octetos para identificar la red y los dos restantes para identificar los hosts. Comprende las direcciones desde 128.0.0.0 hasta 191.255.255.255. Su máscara tradicional era 255.255.0.0 (/16).
    • Clase C: se utilizaba para redes pequeñas, con un número más limitado de dispositivos. Los tres primeros octetos identificaban la red y el último identificaba los hosts. Comprende las direcciones desde 192.0.0.0 hasta 223.255.255.255. Su máscara tradicional era 255.255.255.0 (/24).
    • Clase D: se destinaba a la multidifusión (multicast), un mecanismo que permite enviar paquetes de datos a un grupo de dispositivos que han manifestado interés en recibirlos. En lugar de enviar una copia individual a cada destinatario, el emisor envía los datos a una dirección de multidifusión y la red se encarga de distribuirlos a los miembros del grupo. Este mecanismo resulta útil, por ejemplo, para distribuir transmisiones de vídeo o información a varios dispositivos simultáneamente. Las direcciones IPv4 de clase D se encuentran en el rango 224.0.0.0 a 239.255.255.255.
    • Clase E: se reservaba para usos experimentales y otros fines especiales. Comprende las direcciones desde 240.0.0.0 hasta 255.255.255.255, aunque existen excepciones, como 255.255.255.255, que se utiliza como dirección de difusión limitada (limited broadcast). Por tanto, no todo el rango de la clase E puede considerarse disponible para experimentación. Un ejemplo de dirección de este rango es 240.0.0.1, que no se utiliza normalmente para asignar una dirección IPv4 a un dispositivo en una red convencional.
    Clase Primer octeto Rango de direcciones IPv4 Máscara tradicional Uso
    A 0-127 0.0.0.0 - 127.255.255.255 255.0.0.0 (/8) Redes muy grandes
    B 128-191 128.0.0.0 - 191.255.255.255 255.255.0.0 (/16) Redes medianas
    C 192-223 192.0.0.0 - 223.255.255.255 255.255.255.0 (/24) Redes pequeñas
    D 224-239 224.0.0.0 - 239.255.255.255 No aplicable Multidifusión (multicast)
    E 240-255 240.0.0.0 - 255.255.255.255 No aplicable Usos experimentales o especiales

    Consideraciones importantes:

    • En la clase A:

      • El bloque 0.0.0.0/8 (es decir, de 0.0.0.0 a 0.255.255.255) tiene usos especiales, como representar una dirección IP no especificada. No se utiliza para asignar direcciones convencionales a dispositivos de una red.
      • El bloque 127.0.0.0/8 (es decir, de 127.0.0.0 a 127.255.255.255) se reserva para loopback, es decir, para que un dispositivo se comunique consigo mismo.

      Por ello, las redes convencionales de clase A utilizaban los primeros octetos del 1 al 126.

      Nota

      La dirección 127.0.0.1, conocida como localhost, permite a un equipo comunicarse consigo mismo sin enviar los datos a través de la red física. Pertenece al rango 127.0.0.0/8, reservado para loopback. Aunque 127.0.0.1 es la dirección más utilizada, cualquier dirección de ese rango está reservada para este propósito. Por ejemplo, se puede utilizar http://localhost:8080 para acceder a un servidor web que se ejecuta en el propio equipo y escucha en el puerto 8080.

    • En la clase E, 255.255.255.255 es la dirección de difusión limitada (limited broadcast), por lo que no todas las direcciones de este rango se destinan a experimentación.

      Nota

      La difusión limitada (limited broadcast) es un mecanismo de IPv4 que permite enviar un paquete a todos los dispositivos de la red local a la que está conectado el emisor, sin que los routers lo reenvíen a otras redes.

    Sin embargo, el direccionamiento por clases ya no es el sistema utilizado para diseñar las redes actuales. Su estudio resulta útil para comprender la evolución del direccionamiento IPv4, pero las redes modernas utilizan principalmente direccionamiento sin clases mediante máscaras de longitud variable y notación CIDR.

    B. Máscaras de subred

    Una máscara de subred es una secuencia de 32 bits que permite determinar qué parte de una dirección IPv4 corresponde a la red y qué parte corresponde al host. Se utiliza junto con la dirección IP para determinar a qué subred pertenece un dispositivo y si otro dispositivo se encuentra en esa misma subred.

    En la máscara, los bits que corresponden a la red se representan mediante 1, mientras que los bits correspondientes al host se representan mediante 0.

    Por ejemplo, una máscara /24 equivale a:

    11111111.11111111.11111111.00000000

    Su representación decimal es 255.255.255.0. Esto significa que los primeros 24 bits identifican la subred y los 8 bits restantes permiten identificar los hosts dentro de ella.

    Si utilizamos una máscara /26, los primeros 26 bits identifican la subred y quedan 6 bits para los hosts:

    11111111.11111111.11111111.11000000

    Su representación decimal es 255.255.255.192. Los dos primeros bits del último octeto también se utilizan para identificar la subred, por lo que se pueden crear cuatro subredes a partir de una red /24. Cada una dispone de 64 direcciones en total, de las cuales 62 se pueden asignar normalmente a dispositivos.

    La notación /24 o /26, denominada longitud del prefijo, indica precisamente cuántos bits consecutivos de la máscara tienen valor 1.

    ¿Qué es una subred?

    Una subred es una división lógica de una red IP que permite organizar los dispositivos en diferentes grupos. Cada subred dispone de su propio rango de direcciones IPv4 y se identifica mediante una dirección de red y una máscara.

    Por ejemplo

    Un centro educativo dispone de una red para los ordenadores de administración, otra para los equipos de las aulas de informática y una tercera para los dispositivos del profesorado. Para organizar la red, el administrador configura tres subredes IP diferentes, cada una con su propio rango de direcciones. Aunque los equipos estén conectados a los mismos switches físicos, la comunicación entre subredes requiere un router o un switch de nivel 3 que se encargue de encaminar los paquetes entre ellas.

    La división en subredes permite:

    1. Organizar los dispositivos en grupos independientes, facilitando la administración de las direcciones IP y la configuración de la red.
    2. Separar los dominios de difusión cuando los dispositivos se distribuyen en redes locales independientes, por ejemplo, mediante VLAN. De este modo, los mensajes de difusión de una red no se propagan directamente a las demás.
    3. Reducir el tráfico innecesario y facilitar el control de las comunicaciones entre los distintos grupos de dispositivos.

    Cuando un dispositivo quiere enviar datos a otro, utiliza la dirección IP y la máscara de subred para determinar si el destinatario pertenece a su misma subred:

    • Si ambos están en la misma subred, puede enviar los datos directamente al destinatario a través de la red local.
    • Si pertenecen a subredes diferentes, envía los datos a la puerta de enlace predeterminada, que se encarga de encaminarlos hacia la red de destino.

    Por ejemplo

    Un ordenador tiene la dirección 192.168.1.10 y la máscara 255.255.255.0 (/24). Su dirección de red es 192.168.1.0, ya que los primeros tres octetos identifican la subred y el último identifica al host.

    En esta subred, las direcciones tienen la siguiente función:

    • Dirección de red: 192.168.1.0. Identifica la subred y no se asigna normalmente a un host.
    • Direcciones de host: desde 192.168.1.1 hasta 192.168.1.254. Pueden asignarse a dispositivos.
    • Dirección de difusión: 192.168.1.255. Permite enviar paquetes de difusión a los dispositivos de esa subred.

    Por tanto, un ordenador con dirección 192.168.1.20/24 pertenece a la misma subred que 192.168.1.10/24. En cambio, un ordenador con dirección 192.168.2.20/24 pertenece a otra subred, por lo que la comunicación entre ambos requiere normalmente encaminamiento.

    División de una red en subredes:

    La máscara también permite dividir un bloque de direcciones en varias subredes más pequeñas. Para conseguirlo, se amplía el prefijo, utilizando como bits de red algunos de los que antes se destinaban a identificar los hosts. Cuanto más largo es el prefijo, menos bits quedan para los hosts y menor es el tamaño de cada subred.

    Por ejemplo

    Por ejemplo, partimos de la misma red del ejemplo anterior, 192.168.1.0/24, que dispone de 256 direcciones en total. En una subred convencional, dos de ellas se reservan para identificar la red y la difusión, por lo que quedan 254 direcciones asignables a hosts.

    Si necesitamos dividirla en cuatro subredes iguales, podemos utilizar una máscara /26, equivalente a 255.255.255.192:

    11111111.11111111.11111111.11000000

    La nueva máscara utiliza dos bits adicionales para identificar las subredes. Con dos bits se pueden representar cuatro combinaciones diferentes: 00, 01, 10 y 11. Por tanto, se obtienen cuatro subredes, cada una con 64 direcciones totales y 62 direcciones asignables a hosts.

    Las cuatro subredes resultantes son:

    Subred Dirección de red Primer host Último host Difusión
    1 192.168.1.0/26 192.168.1.1 192.168.1.62 192.168.1.63
    2 192.168.1.64/26 192.168.1.65 192.168.1.126 192.168.1.127
    3 192.168.1.128/26 192.168.1.129 192.168.1.190 192.168.1.191
    4 192.168.1.192/26 192.168.1.193 192.168.1.254 192.168.1.255

    También podemos crear subredes de tamaños diferentes. Por ejemplo, si necesitamos una subred grande y dos más pequeñas, podemos dividir el bloque inicial de forma desigual mediante máscaras diferentes. Esta técnica se conoce como VLSM (Variable Length Subnet Mask).

    C. Notación CIDR

    La notación CIDR (Classless Inter-Domain Routing) permite expresar redes IPv4 mediante un prefijo que indica su tamaño, sin depender de las antiguas clases A, B y C.

    Por ejemplo, la expresión 192.168.1.0/26 identifica un bloque de direcciones cuyo prefijo tiene 26 bits. Esta notación permite representar redes de diferentes tamaños con independencia de las clases tradicionales.

    Antes de CIDR, las máscaras predeterminadas dependían de la clase de la dirección: /8 para la clase A, /16 para la B y /24 para la C. CIDR eliminó esta limitación y permitió asignar bloques de direcciones ajustados a las necesidades de cada red, aprovechando mejor el espacio de direccionamiento IPv4.

    Actualmente, la notación CIDR se utiliza habitualmente para expresar redes, bloques de direcciones y rutas de encaminamiento.

    3.3. Protocolos TCP/IP de nivel superior

    Los protocolos de las capas superiores proporcionan servicios que utilizan las aplicaciones para comunicarse a través de la red. Algunos de los protocolos más conocidos de la familia TCP/IP son los siguientes:

    • FTP (File Transfer Protocol) permite transferir archivos entre un cliente y un servidor. Es un protocolo tradicional de transferencia de archivos y, debido a que no cifra por sí mismo la comunicación, actualmente se prefieren alternativas seguras cuando se necesita transferir información sensible.

    • SNMP (Simple Network Management Protocol) se utiliza para la supervisión y gestión de dispositivos de red. Permite obtener información sobre el estado y funcionamiento de determinados equipos y servicios.

    • HTTP (Hypertext Transfer Protocol) es uno de los principales protocolos utilizados para la transferencia de recursos en la web. La versión protegida mediante cifrado, HTTPS, utiliza HTTP sobre una conexión segura mediante TLS.

    • RPC (Remote Procedure Call) permite que una aplicación solicite la ejecución de determinadas operaciones en otro sistema, facilitando la comunicación entre aplicaciones distribuidas.

    • SMTP (Simple Mail Transfer Protocol) se utiliza principalmente para el envío y la transferencia de correo electrónico entre clientes y servidores y entre servidores de correo.

    • POP3 (Post Office Protocol version 3) permite descargar mensajes de correo electrónico desde un servidor a un cliente. Está pensado principalmente para la recepción y descarga de los mensajes.

    • IMAP (Internet Message Access Protocol) permite acceder al correo almacenado en un servidor y gestionar los mensajes manteniéndolos en dicho servidor. Esto facilita el acceso al mismo buzón desde diferentes dispositivos.

    Estos protocolos muestran que TCP/IP no se limita a transportar paquetes entre equipos. Sobre la infraestructura proporcionada por IP y los protocolos de transporte se construyen numerosos servicios que utilizan directamente las aplicaciones.

    3.4. Utilidades propias de redes TCP/IP

    Los sistemas operativos incorporan diferentes herramientas que permiten consultar la configuración de red, comprobar la conectividad y diagnosticar problemas. Estas utilidades son especialmente importantes para el administrador o técnico de redes, ya que permiten obtener información sobre el funcionamiento de un equipo sin necesidad de utilizar herramientas gráficas específicas.

    A. Utilidad ping

    ping permite comprobar la conectividad IP con otro dispositivo mediante mensajes ICMP. Envía solicitudes de eco y muestra las respuestas recibidas, así como el tiempo de ida y vuelta.

    Por ejemplo:

    ping 192.168.1.1

    Si el destino responde, ping permite comprobar que existe conectividad IP entre ambos dispositivos. También puede utilizarse con nombres de host para comprobar si la resolución de nombres funciona correctamente. Microsoft mantiene esta utilidad en las versiones actuales de Windows y la documenta expresamente como una herramienta principal para diagnosticar conectividad y resolución de nombres.

    B. Utilidades arp e ip neigh

    En IPv4, arp permite consultar y modificar la caché ARP, donde se almacenan asociaciones entre direcciones IPv4 y direcciones físicas de la red local. Por ejemplo, en Windows:

    arp -a

    muestra las entradas actuales de la caché ARP.

    En sistemas GNU/Linux modernos, la utilidad ip proporciona mecanismos para consultar esta información, por ejemplo mediante ip neigh. Por ello, aunque arp sigue siendo útil para comprender y diagnosticar IPv4, conviene conocer también las herramientas actuales de administración de red.

    C. Utilidades de configuración de red

    En Windows, ipconfig permite consultar la configuración TCP/IP de los adaptadores de red y realizar determinadas operaciones relacionadas con DHCP y DNS. Por ejemplo:

    ipconfig
ipconfig /all

    La opción /all proporciona información más detallada sobre los adaptadores, incluyendo direcciones IP, máscara de subred y puerta de enlace predeterminada.

    En GNU/Linux, la herramienta moderna para consultar y configurar interfaces, direcciones y otros parámetros de red es ip. Por ejemplo:

    ip address

    permite consultar las direcciones configuradas en las interfaces de red.

    Las herramientas antiguas como ifconfig e iwconfig todavía pueden encontrarse en algunos sistemas o materiales didácticos, pero no deben presentarse como las herramientas principales de administración de red actuales.

    D. Utilidad netstat y ss

    netstat permite consultar información sobre conexiones de red, puertos en escucha, estadísticas y otros datos relacionados con TCP/IP. Por ejemplo, puede utilizarse para comprobar qué conexiones TCP están activas o qué puertos están siendo utilizados.

    En sistemas actuales, especialmente en GNU/Linux, ss es una herramienta moderna que proporciona información equivalente y más completa sobre sockets y conexiones de red.

    En Windows, netstat continúa estando disponible y permite consultar conexiones TCP activas y puertos en escucha.

    E. Utilidad route y ip route

    La utilidad route permite consultar y modificar la tabla de enrutamiento IP del equipo. Esta tabla determina qué camino debe utilizar el sistema para enviar los paquetes hacia las diferentes redes.

    En Windows, por ejemplo:

    route print

    permite consultar la tabla de rutas. El comando route continúa disponible en las versiones actuales de Windows.

    En GNU/Linux, la herramienta habitual es:

    ip route

    La consulta de la tabla de rutas resulta especialmente útil cuando un equipo puede comunicarse con algunos dispositivos de la red, pero no puede alcanzar otras redes.

    F. Utilidades tracert, traceroute y tracepath

    Estas herramientas permiten conocer los saltos que realiza un paquete desde el equipo de origen hasta un destino.

    En Windows se utiliza:

    tracert destino

    mientras que en GNU/Linux pueden utilizarse herramientas como:

    traceroute destino

    o:

    tracepath destino

    tracert utiliza valores crecientes del campo TTL para identificar los dispositivos intermedios de la ruta y mostrar los tiempos de respuesta correspondientes.

    Estas herramientas son especialmente útiles para localizar en qué punto de una ruta puede estar produciéndose un problema de conectividad o un aumento de la latencia.

    G. Utilidades ftp y tftp

    ftp permite realizar transferencias de archivos mediante el protocolo FTP. El modelo de funcionamiento incluye un cliente y un servidor FTP.

    TFTP (Trivial File Transfer Protocol) es una versión mucho más sencilla de este mecanismo y utiliza UDP. Se ha empleado tradicionalmente en determinados escenarios de red, como algunas operaciones de configuración o arranque de dispositivos.

    Aunque estos protocolos siguen existiendo y pueden encontrarse en determinados entornos, FTP y especialmente TFTP no deben confundirse con las alternativas modernas y seguras para la transferencia de archivos. FTP no cifra por defecto las credenciales ni los datos que transmite.

    H. Utilidades telnet y ssh

    telnet permite establecer una conexión remota mediante una interfaz de terminal. Sin embargo, sus comunicaciones no están cifradas, por lo que no debe utilizarse para administrar sistemas a través de redes no confiables.

    La alternativa habitual para la administración remota segura es SSH (Secure Shell). SSH proporciona una conexión cifrada y permite acceder remotamente a un sistema mediante una terminal, además de ofrecer otros mecanismos de administración y transferencia segura.

    Por este motivo, al estudiar las conexiones remotas es importante conocer telnet como tecnología histórica y de diagnóstico en determinados entornos, pero utilizar SSH como referencia actual para la administración remota segura.
